# n = 100：把 n = 25 的环状目标函数推广到 100 盘

状态层：`runtime/n100_polar_probe.json`、`runtime/freecover_n100.json`、
`runtime/rings_cover_regression.log`。
机具：`tools/rings_cover.py`（目标函数）、`tools/rings_scan.py`（通用枚举）、
`tools/freecover.py`（非环对照组）。
探针：`_recon/benchmark/n100_polar_probe.py`。

> 本文件只写**已跑出数字**的东西。所有结论都注明强度等级：
> **①覆盖**（这个构型确实以半径 r 覆盖单位圆盘）、**②族内最优**（在 C_k 环族内是最优的，
> 但族本身是限制）、**③全局最优**（r_D(100) = r）。本轮**没有任何 ③**。

## 1. 推广了什么

n = 25 的机具（`_recon/benchmark/svg/n25_candidates.py` → `verify/coverage_cert_n25.py`）
是一个**同心正多边形环族**上的覆盖半径目标函数：

```
cover_radius(F) = max_{|x| <= 1} min_i |x - c_i|
```

其中 `F` = 一个中心盘 + 若干同心环 `(m_j, rho_j, phi_j)`。推广到任意 n 只需要两件事：

1. **把硬编码的 8 去掉**，换成 `k | m_j`（`k` = 旋转对称阶 C_k）；
2. **把候选点全集限制到基本扇区** `[0, 2*pi/k]`。

第 2 步是精确的，理由是一条轨道论证：全局最大点 `x*` 的整条 C_k 轨道全是最速点，
轨道必与闭合扇区相交，而群把「三点的外心」映成「三点的外心」，所以那个交点在候选集里。

候选点引理（与 n = 25 证书同一条）：

| 类型 | 位置 |
|---|---|
| 内部极大 | 三心外心（Voronoi 顶点）／两心中点（退化共线）／原点 |
| 边界极大 | 某对心的垂直平分线与单位圆的交点／对跖点 `-c_i/\|c_i\|` |

## 3. n = 100 的轨道算术

C_k 不变的构型里，每个环的点数是 k 的倍数，于是

```
100 = c + k*(u_1 + ... + u_q),   c ∈ {0,1},  u_j >= 1
```

k = 6, 7, 8 **算术上不可能**（6 ∤ 100 且 6 ∤ 99；7, 8 同理）。
可用：k = 1, 2, 3+中心, 4, 5, 9+中心, 10, 11+中心, 12, …

## 4. 三条结构事实（都是算出来的，不是猜的）

**(a) 最外环的下限。** 半径 r 的盘要盖住单位圆，其圆心半径 `rho` 必须满足
`cos(pi/m) = (1 + rho^2 - r^2)/(2 rho)`；右端在 `rho ∈ (0,1]` 上的最小值是 `sqrt(1-r^2)`，
所以

```
m >= pi / arccos(sqrt(1 - r^2))  ~  pi / r
```

r ≈ 0.123 时 `m >= 26`。这个约束是 n = 100 与 n = 25 在结构上最大的不同：
n = 25 的最外环只有 8 个点。

**(b) 环族会塌成极坐标网格。** 所有找到的好构型都是「半径与点数成正比」的极坐标网格
`m_j ≈ c * rho_j`、相邻环错开半步。这种网格的覆盖半径有闭式近似

```
r ≈ sqrt( (d_rho/2)^2 + (pi/c)^2 )
```

**(c) 环族的硬约束。** `k | m_j` 使得径向步长只能是 `k*Delta_u/c`，
于是**不可能同时**让径向步长和角向步长都取到最优 —— 大洞总是出现在「点数被迫跳一档」
的那个半径区间。n = 100 上这就是环族对六方铺砌的固定亏损。

## 5. n = 100 的数字

| 量 | 值 | 强度 |
|---|---|---|
| 平凡面积下界 `1/√100` | 0.100000 | ③ 下界（弱） |
| 六方密度渐近 `sqrt(delta/100)` | 0.109964 | 渐近（非有限 n 定理） |
| 外推 `E√n ≈ 0.91`（n≤25 拟合） | ≈0.1149 | 外推，**不是定理** |
| **六方点阵补丁，100 盘** | **0.122343271328** | ① 覆盖 |
| **最优 C_k 环构型** | **0.1231779180** | ①② |

**六方点阵补丁**：`a = 0.211905`，取格点 `|p| <= 1 + a/√3` 中最靠近原点的 100 个
（85 个在单位盘内，15 个在 `1 < |p| <= 1.1223` 的环带里）。
覆盖半径恰为 `a/√3 = 0.122343271328`，用三种互相独立的方法复核一致：
全三元组枚举、Delaunay 外心、1400×1400 网格（网格给 0.122239286，按定义是下界）。

**最优 C_k 环构型**：k = 11 + 中心盘，5 个环 `(11, 11, 22, 22, 33)`，
半径 0.2313 / 0.4116 / 0.5563 / 0.7461 / 0.9171，r = **0.1231779180**。

```
环族亏损 = 0.1231779180 / 0.1223432713 - 1 = +0.68%
```

**非环对照组（自由点松弛）**：`tools/freecover.py`，初值 = 上面那个六方补丁，
12 个随机种子各跑 8000 轮「最深洞」松弛 —— **12 个种子全部原地返回
0.122343271328，一个中心都没挪动**。结论：这个六方补丁至少是 max–min 泛函的
**局部最优**，单点搬迁无法改进它。

**所以本轮的答案是**：n = 100 时，

```
最好的构型   r = 0.122343271328   （六方点阵补丁，局部最优）
最好的环构型 r = 0.1231779180     （k = 11 + 中心，比上面差 0.68%）
```

也就是说：**把 n = 25 那台环状机具原样推到 100 盘，它比一条普通的六方点阵补丁还差 0.68%。**
道理是清楚的：n = 25 的答案由边界效应主导（最外环只有 8 个点，中心盘撑住内部），
n = 100 由体相主导，而环族**在结构上表达不出六方体相**（第 4(b)(c) 条）。
环族随 n 增大而相对变差，这一点在 n = 19 上已经有苗头：那里环构型（6+6+6+中心）
和最好的六方补丁几乎打平（0.27735 对 0.27745），到 n = 100 就落后了。

## 6. 诚实边界（必须随结果一起走）

- ① 覆盖：第 5 节两个构型的覆盖半径是**这个构型**的覆盖半径，已复核。
- ② 族内最优：`0.1231779180` 是**枚举过的 C_k 环族**里最好的，不是「环族最优」。枚举方式为
  「极坐标网格族 + 5 个结构化初值 + 模式搜索」；非单调的点数配置没进枚举空间。
- ③ 全局最优：**什么都没证**。既没有 `r_D(100) >= ...` 的下界，也没有任何全局最优性断言。
- 0.1149 那个外推是 n ≤ 25 的 `E√n` 拟合（观测值散在 0.80–1.18），**不是定理**。
  它低于两个构型 6%，只说明「我们的构型可能还差 6%」，不说明真值就是 0.1149。

## 7. 本轮踩到的三个坑（都改了代码）

1. **`extra=[]` 让目标函数静默返回 1e3。** `np.atleast_2d(np.asarray([]))` 形状是 `(1,0)`，
   `len(E)==1` 为真 → `np.concatenate` 抛异常 → `objective_factory` 把异常吞掉返回 1e3。
   后果：**每一次优化都原地返回初值**，而报表上印的却是合法的审计半径。第一版 n = 100
   「结果」（0.153 / 0.1366）全是初值假象。现在 `strict=True` 默认让异常直接冒出来。
2. **三元组子采样会漏掉最深洞。** cap = 4000/161700 时，一个 0.1223 的构型被报成 0.1223，
   而真值是 0.2122（74% 误差）；根因是 Voronoi 顶点的定义三元组**不一定**互为最近邻。
3. **scipy 的 Powell 在这个维度不可用。** 它的线搜索每个方向花约 100 次求值，
   2q = 16 维 × 80 轮 ≈ 10^5 次 → 单个环配置要几小时。换成**有求值预算的 compass search**。

修完后加了一条硬加速：**Delaunay 外心 = Voronoi 顶点**，所以候选集可以从 O(N³) 降到 O(N)，
且**精确**（随机 12 个环构型上 Delaunay 与全枚举逐位一致）。n = 100 单次求值
从 ~45 ms 降到 ~1 ms。

## 8. 非单调点数 profile（后来的补充）

上面第 5 节的枚举空间漏了一整类：**profile 是有序的，不是多重集**。`_unpack` 按半径排序并
保持「半径↔点数」配对，所以 `(4,12,20)` 和 `(20,12,4)` 是**两个不同构型**（大环在内还是在外），
而极坐标探针只生成了递增的 `u_j = round(βj)`。

`tools/rings_profile_search.py` 补上了这一块：对**有序** profile 做 beam search，邻域 = 交换两点数 /
在两环间搬 k 个点 / 合并两环 / 拆一环，全部保持点数总和。结果：

- 本机冒烟立即找到一个真非单调 profile `[10, 20, 10, 30, 30]`（k=10，无中心），
  说明这类构型确实可达 —— 但它的半径 0.1256 比最优极坐标型 0.12318 差。
- 服务器跑完整一轮邻域（359 个邻居）**没有改过 0.1231779180**。即：
  **已探索的 1-步非单调邻域里没有更好的东西。**

诚实说明：这一轮 beam 只有 3 轮就因邻域耗尽而收敛，而且**塌到了单一 k 族**（k=11）。
已改成「每个 (k, centre) 族至少留一个代表」的多样化 beam，正在服务器上重跑（beam 14，
9 个族，20 轮），结果待收。

## 9. Stage 2（n = 25 逐胞不等式）的第一手结论

见 `docs/notes-n25-cellbound.md`。一句话：

```
逐胞不等式按目前能合法聚合的形式，在 n = 25 上给出 0.222201，比精确值 0.239146 低 7.09%
—— 不满足 goal §G 的 5% 判据。
但用最优构型自己的胞结构算是 0.228939（低 4.27%）。
```

差的 2.8 个百分点在**聚合**（边界 Euler 记账），不在胞不等式本身。所以「先做 n = 25 逐胞」
这一步的答案是：**当前形式太弱，必须先补边界 Euler 记账，才能谈 n = 100 的下界。**
