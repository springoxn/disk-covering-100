# 阶段123：半径条件计数与实际耳装饰域接口

## 已执行证据

[计数域接口](../verify/n100_count_proof_interfaces.py)新增radius_joint和ear_marked两项必要域筛选，以及显式count_to_actual_ear_decoration适配。[测试入口](../verify/n100_count_proof_interface_contracts.py)实际退出0，[本轮证书](../verify/out/n100-count-proof-interface-contracts.json)记录完整有限重放和边界控制。

当前六项中心盒叶保持第三版接口不变；本批是不同类型的计数域接口，不能与中心盒结果直接拼接。前批规划契约radius_local_joint对应本批radius_joint，ear_marked_joint对应本批ear_marked；recursive_count仍作为继承的前置必要域，未声称此次重新求解完整递归前沿。

## 类型契约

输入必须声明n=100、semantics_id=normalized-distinct-boundary-cells/v1、configuration_id、radius_units=radius、正有理radius_upper和整数tuple列表。

三元组为(m,B,k)：m是当前归约覆盖的有效圆盘数，B是同一规范化单弧图中的不同边界细胞数，k是不同圆周服务圆盘数。输入检查1<=B<=k<=m<=100；这不是B=k假设。

四元组另带实际耳数e。耳装饰输入还要求m>B及0<=e<=floor(B/2)，适配器明确继承有内部顶点时耳尖不相邻的组合引理。任意所有权弧段数不能作为B输入；错误语义id被拒绝。

结果为EXCLUDED或NOT_EXCLUDED，仅描述所声明计数分支必要域的筛选。存活标签不是覆盖、内部地图或几何可行性证据。输出绑定规范输入哈希、所用半径层、继承前提和输入文件/脚本哈希。

## 半径域与组合

每层证书在r<=上端点范围内有效。接口选择所有可用层中最小上端点的一层，保持较强必要域；不把报告中的下端点当作不相交分区，也不要求同一几何代表跨半径保持不变。

本轮对同一最大层404三元组分别应用四层筛选，完整结果逐项匹配原证书：93、193、319、404。候选整数标签(100,32,32)在四层保留，不解释为较小半径可行。

耳装饰适配枚举每个输入(m,B,k)的全部允许e=0..floor(B/2)，保留配置、半径和表示语义，返回父输入指纹及组合前提。只有显式经过该适配，三元组域才能转成四元组域。

ear_marked先应用计数必要域，再在认证端点内应用实际耳数必要域，按逻辑求交。它不把旧kappa联合面积和新实际耳标记面积的亏损相加；后者替换面积预算。半径超过耳认证端点时不套用耳数限制，输出ear_bound_applied=false，仍可应用适当计数层。
