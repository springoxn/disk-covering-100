# n=100 阶段26：盒内共同圆心与候选来源排除

**当前区间未改变；全局最优性和最优半径极小多项式未完成。**本轮新增了可应用于真实候选来源中心盒的精确排除器。

## 1. 盒内共同圆心约束

脚本：`verify/n100_box_aware_capacity.py`，实际退出0；证书：`verify/out/n100-box-aware-capacity.json`。

对见证集合S及其均值pbar，恒等式

`sum_{p in S} |c-p|^2 = |S|*|c-pbar|^2 + sum_{p in S}|p-pbar|^2`

给出盒K内的平均距离平方下界

`dist(pbar,K)^2 + (1/|S|)*sum |p-pbar|^2`。

若严格大于半径平方上端t，盒内任何单一圆心都不能同时覆盖S。所有判定使用Fraction。主实现计算均值/方差；独立实现把均值投影到矩形盒后，直接累计到全部见证的距离平方。这里只采用等权平均支持，所以保留的模式可以偏松；绝不把没有发现反证当作真正可行。

每个盘保留其所有未排除模式的极大子集。有限并集动态规划检查100个盘各选择一个模式后，是否能覆盖整个见证池。覆盖较大的状态支配其子集；独立实现不做支配剪枝，重新枚举并集状态。闭端点等号保留，严格大于才排除。

两个校准案例都被旧的全池容量界漏掉而被新实现排除：

1. 两个点各自能到达圆心盒，也能由一个不限位置的圆心覆盖，但盒内没有共同圆心。
2. 局部两点存在资源缺额，第三个无关点却有多个可用盘，使旧全池容量总和无法发现缺额。

共同圆心可行控制不被排除；遗漏可行模式、虚构单点排除、篡改最终并集结论三项损坏均拒绝。

## 2. 实际候选来源的32个中心盒

脚本：`verify/n100_candidate_pattern_pruning.py`，实际退出0；证书：`verify/out/n100-candidate-pattern-pruning.json`。

输入绑定候选的932变量有理中点与KKT系统。前8个内部活跃孔的有理中点作为见证；全部被精确检查位于单位圆盘内，不将中点误称为代数根孔。

对每个孔，将其三个支撑中心从孔向外移动原相对向量的1/100，其余中心保留中点。分别取中心坐标盒半宽1/10^6、1/10^4、1/1000、1/100，共32个明确列出的域。盒允许独立变化，不假设接触等式仍成立，因此证书排除的是这些中心盒中的所有覆盖配置。

结果：**16盒排除，16盒未决**。不能把这些有限盒当作完整候选图域、候选邻域覆盖或全部地图族排除。未移动的候选中心盒在三种宽度下均未排除。一个已排除盒按精确有理切点分为两个闭子盒，独立核查继承关系并重算两片排除。

## 3. 边界计数接口与子代理审查修正

指定DeepSeek V4.1 Flash（OpenCode Go）子代理完成只读审查。其可靠部分是：服务盘数k与规范化边界拥有者数B须区分；在已接受的单弧归约条件下有B<=k，不能令k=B。

审查有两项错误，已由主线程修正：

- 外部反转分支单射不意味着整个分段norm-cap归约单射。取内圆心模d1=9/10，以及外圆心模(1-U^2)/d1，前者不变而后者反转后与前者重合。有效中心数可能降低，必须由归约后新图重算。
- 建议用k<=psi(B)<B联合，与B<=k本身矛盾，不能作为研究路线。

精确控制入口：`verify/n100_boundary_interface_controls.py`，退出0；证书：`verify/out/n100-boundary-interface-controls.json`。同向圆心模9/10和99/100均在norm cap内；内盘有非空圆周服务弧，但整弧严格更靠近外圆心。因此norm cap不保证每个服务盘拥有圆周弧。这是两站点几何控制，不冒称构造了完整100盘反例覆盖。

子代理提出的弧长—帽面积耦合只给了浮点发现，无精确证书；本轮不接受其k<=54的推测。现有简单帽面积界不能据此被升级。
