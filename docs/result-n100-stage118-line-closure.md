# 阶段118：当前m99边界线路收尾与接口研究阶段边界

用户指定顺序：先收尾当前线路，再整理全部剪枝为可组合证明接口，之后研究独立复杂度/时间预测及组合可行性。新阶段不以证明完整n100最优性为收尾条件。

## 已完成的线路边界

当前线路是阶段117的m99六家族必要边界模式生成、真实不交耳组打包及联合面积筛选。它不是内部三角地图生成器，不处理m100全部边界代表，也不排除完整家族。

新增入口[隔离重放器](../verify/run_n100_boundary_line_replay.py)，用5个脚本与2份输入构建独立目录，按顺序重跑主生成与独立复核，原证书保持不动。两个输出都要求与当前参考JSON完全相等；哈希亦记录。若子进程失败保存失败状态并停止，运行目录已存在则拒绝覆盖。

复现：在项目根执行下式，指定一个尚不存在的新目录。

```powershell
python verify/run_n100_boundary_line_replay.py --run-dir runtime/boundary-line-replay-fresh
```

实际运行在[隔离报告](../runtime/boundary-line-replay-118/replay.json)：主/独立退出0，3601->327，两份证书与参考SHA256完全相同。这里验的是当前线路在最小依赖上的端到端重放，不重新验证前置角度归约或所有历史证据。

一次本机端到端耗时：主生成2182431400ns，独立核验1972014600ns。记录的是整进程墙钟，不含隔离复制阶段。一次样本不能解释成均值、上界、硬件无关速度或完整地图搜索时间。时间遥测不参与任何几何接受判定。

## 接口整理的完成判据

1. 清点verify下全部n100相关脚本及其证书，区分可调用剪枝、证书重放、反例/负控制、已撤回判定、基准与中间产物；不能把一个阶段等同一种独立剪枝。
2. 每个剪枝给稳定id、输入对象类型、参数域与坐标/半径语义、解析前提、证明预算、返回结果类型、证书及独立核验入口。
3. 至少使用EXCLUDED / NOT_EXCLUDED / UNDECIDED / PRECONDITION_MISSING区分输出；不让存活冒充几何可行。
4. 组合验证检查同一配置/图/半径归一化、输入域包含关系、依赖DAG、重复预算和局部/全局范围。旧错误和撤回项必须标记，不能自动重新启用。
5. 对“都有效但不可直接相加”“可以串联求交”“依赖相同松弛且被支配”“叶证书可以混合而树覆盖仍需另验”分别给规则和可执行检查。

## 复杂度/时间研究的完成判据

每种有效剪枝先独立分析，再研究组合：

- 计入输入规模、整系数/有理位长和高精度根包络代价；指数搜索和证书线性重放分别计价。
- 区分预计算、每节点判定、发现搜索、证书验证、I/O及缓存构建；给明确单位和适用工作负载。
- 先小规模局部校准，记录机器、Python、样本规模、重复次数、运行顺序、缓存策略；不把计时浮点用于数学判定。
- 外推必须列模型、校准区间和不确定性，不以少量未决盒的排除率预测整个未知地图域。
- 组合收益同时受顺序、重叠排除、共享缓存与前提建立成本影响；不能独立通过率简单相乘。
- 未知输入分布、未知完整地图数、未实现算法明确标不可可靠预测，不制造秒级全局求解估计。
