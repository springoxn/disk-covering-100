# n = 100 等圆盘覆盖单位圆盘：证书、方法与失败路线

> **当前可验证结论**：
> 
> `r_D(100) > 0.113235` 已有六分支证书；`0.11324` 尚未闭合，B36 仍有严格残余。
> 
> 同一公开包还保留一个已重放的构型上界：
> 
> `0.113235 < r_D(100) <= 0.1154469548855829`。
> 
> 这里的上界来自一个具体的100圆盘构型；它不是最优性证明。下界是六个组合/几何分支的排除证书；它不是“找到一个半径就自动得到”的数值优化结果。

本仓库的目标不是只展示一条漂亮的成功路径，而是公开：问题背景、当前上下界怎样得到、哪些前提仍依赖几何归约、哪些路线被证伪或只留下诊断、以及如何从证书重新运行。

## 1. 问题背景

令 `D = {x in R^2 : |x| <= 1}`。定义 `r_D(100)` 为用100个半径相同的闭圆盘覆盖 `D` 所需的最小半径：

```text
r_D(100) = inf { r : D ⊆ ⋃_{i=1}^{100} B(c_i,r), c_i ∈ R² }.
```

这是一个连续、非凸、带组合拓扑变化的覆盖优化问题。中心可以重合、落在单位圆盘外，覆盖边界与内部的接触图会随半径变化。因而“随机优化找到一个配置”只能给上界；要给下界，必须排除所有可能的中心配置，而不是只排除某个对称族。

本项目采用闭圆盘、闭单位圆盘和闭区间约定。所有最终判定尽量使用整数、有理数和向外取整的区间运算；浮点搜索只用于发现候选，不作为证书结论。

## 2. 上界：一个明确的100中心构型

上界的逻辑是构造性的：给出100个中心，并验证每个单位圆盘内的点都距某个中心不超过给定半径。公开包包含两层材料：

1. `verify/out/external-disk100-bounds-67ebf1c.json`：当前严格上界重放链，给出
   `r_D(100) <= 1154469548855829/10^16`；
2. `verify/out/lattice97_upperbound_n100.json` 及其独立复核：一个清楚的三角晶格/六角网格构型，半径满足 `alpha² = 1/67`，并明确声明它是构型上界，不是最优性证明。

上界验证的典型步骤是：

- 固定100个中心的精确有理/代数描述；
- 把单位圆盘按边界壳层和内部单元分解；
- 对每个单元检查其最远点（通常是三角形外心或边界切割端点）；
- 用精确平方距离、根区间和边界包含关系验证最大距离不超过候选半径；
- 用独立脚本重算输入哈希、壳层计数、远点排除和候选半径关系。

重要边界：上界证书只说明“存在一个覆盖配置”。它不说明这个配置最优，也不说明三角晶格是唯一或必须的。

## 3. 下界的总框架

当前下界证明采用半径反证：固定一个候选 `R`，假设100个半径`R`的圆盘能覆盖单位圆盘，然后按边界服务数/内部结构分为六个互斥分支：

```text
B31, B32, B33, B34, B35, B>=36.
```

这里 `B` 表示边界上由覆盖胞元服务的有效边界单元数。每个分支再按内部面数 `M`、弦结构、耳结构或标记三角形类型细分。每个细分必须同时完成：

1. 同半径前提检查；
2. 组合类型的穷尽覆盖；
3. 几何/面积不等式的有理区间验证；
4. 预算守恒和严格正余量检查；
5. 将结果写入 `verify/out/*.json`，失败不得伪装成PASS。

### 3.1 B31–B35：组合低阶和高阶分支

这些分支的共同思路是先把可能的覆盖图转成有限的平面图/三角剖分模型，再利用：

- Euler 关系和边面计数；
- 边界服务数与内部面数的关系；
- 标记三角形和边界弧的面积损失；
- 耳分解、非相邻耳删除、核心不等式；
- 对固定 `M` 的有限环模型、无弦模型和单弦模型穷举。

不同分支的实际证书如下：

- B31：低度数/曲率损失路线；
- B32：`M<=25` 与 `M>=26`，含M25专门修复和高M归约；
- B33：低M、高M及唯一度5邻居分裂；
- B34：23个无弦模型和47个单弦模型；
- B35：低M、M25、M26和`M>=27`，其中M25/M26有独立模型账本。

当前直接证书入口：

- `verify/out/n100-B31-at-11324.json`
- `verify/out/n100-B32-complete-149.json`
- `verify/out/n100-B33-complete-167-v2.json`
- `verify/out/n100-B34-complete-180.json`
- `verify/out/n100-B35-complete-203.json`
- `verify/out/n100-B35-M25-M26-complete-201.json`

这些证书是在不小于`0.113235`的半径上建立的排除结果，因此通过半径单调性可用于更小的候选半径；组合总账会显式记录这种继承，而不是把它隐含在叙述中。

### 3.2 B>=36：边界弧预算与pair域证书

高边界数分支把边界弧写成一圈相邻的局部对。对相邻边界单元，构造一个直接损失量，典型结构为：

```text
Phi(a,b) = lambda * |c_a - c_b|² + (H(a)+H(b))/2
           - mu * (asin(s_a)+asin(s_b))/2.
```

其中`a,b`是相邻半弧角，`c_a,c_b`是相应中心，`H`是由弧段和中心到弧弦的几何损失构成的量。程序在二维参数域中做有理矩形细分，逐箱验证上界；相邻项求和时使用精确恒等式

```text
sum_i (a_i+a_{i+1})/2 = sum_i a_i = pi,
```

而不是把等弧Jensen猜想冒充成证明。最后将每个局部pair的上界代入总面积预算，检查B=36处的最小余量，并检查随B增加的斜率为正，于是可覆盖B>=36。

在当前已接受候选 `R=22647/200000=0.113235` 下，B36完整证书实际访问1,841,089个有理箱，其中917,297个接受；q=1/2/3支持箱分别为3761/104/35。对应证书为：

- `verify/out/n100-tail-candidate-224.json`
- `verify/out/n100-candidate-budget-222.json`

## 4. 当前证书链和严格结论

六分支组合证书：

- `verify/out/n100-candidate-complete-225.json`
- `verify/out/n100-six-branch-ledger-226.json`

它们记录：

- B31–B35：引用较大半径上的闭合证书，并用半径单调性继承；
- B36/B>=36：在`R=0.113235`下直接重放；
- 一次性面积预算：总余量和每增加一个边界单元的余量均严格为正；
- `all_six_closed = true`，但这只针对`R=0.113235`，不意味着`R=0.11324`也闭合。

## 5. 尝试过的路线：成功、失败与未决项

下面的列表故意包含失败路线。它们不是噪声，而是说明哪些看似自然的收紧已经被检查过。

### A. 组合/拓扑路线

- 平面图、Dart map、Voronoi所有者和三角剖分编译：用于把连续覆盖转成有限模型；成功产出B31–B35的部分模型，但不能单独完成所有半径分支。
- Euler/耳分解/核心交换：在B31和B35低M中有效；一般高M情形不足以闭合。
- 环模型、无弦模型、单弦模型枚举：成功用于B34/B35高M证书；模型边界必须逐项审计，不能把发现模型当穷尽证明。
- “唯一度5邻居”分裂和M25/M26专门归约：成功解决若干原先缺失的组合类型。

### B. 局部几何与容量路线

- 边界-内部计数、服务数、容量/Hall树、加权见证容量：能发现反例和紧瓶颈，但松弛过宽，未直接给出0.11324全局证书。
- 轴向多锚点、中心盒、空间分支树、Voronoi反向距离：部分盒子可排除，残余盒无法证明为空；因此状态是“剪枝证据”，不是闭合。
- annular cuts、径向层级、方向计数、局部耳、共享顶点和边界圆分支：改善了候选排序和局部排除，但没有完成所有组合接口。

### C. 能量、弧和透镜路线

- 角能量/谐波能量：发现了负见证或反例，说明简单全局角能量不够强。
- 弧帽、弧预算、透镜支撑、Young/支持函数：形成了当前B>=36主路线；在`0.113235`闭合，在`0.11324`被精确障碍点阻塞。
- 直接pair项精细化：把`4 lambda R²`替换为精确中心距并没有产生新信息，因为该项已存在于原始pair表达式；不能把等价重写算作新几何约束。
- 共同端点透镜、跨相邻边界对的联合Jensen/平均：是解决B36的主要未决方向，但目前没有通过的全域证书。

### D. 半径扫描和工程化路线

- 对`0.1132301`到`0.11324`的101个有理半径点做预算/障碍点扫描，定位固定旧参数族的可行窗口；这是诊断图，不是全局证明。
- `0.113236`和`0.113237`曾尝试完整细分，但在窄预算余量下耗时过长，未形成PASS或FAIL证书；不能写成“失败证明”。
- 当前推荐的工程路线是保存可续跑pair箱队列、缓存asin/支持区间、按对角与非对角区域分片，并在每个候选半径上保留独立哈希和退出码。

## 6. 借鉴、依赖和边界

### 6.1 外部库和软件

- Python标准库：`fractions.Fraction`、`decimal`、`math`、`json`、`hashlib`、`pathlib`、`itertools` 等用于最终有理/整数账本。
- SymPy：符号代数、因式检查和部分模型合同；它不是最终数值证书的替代品。
- NumPy：发现阶段的向量化和部分空间/角度实验；浮点结果必须回到有理/区间检查。
- mpmath：高精度候选根和探索；不是最终排除证据。
- 可选的 python-flint/LLL工具只用于部分发现或整数关系实验，不能替代证书中的逐箱有理断言。

发布包没有把第三方源码复制进仓库；依赖脚本的导入行可由`ROUTE_INDEX.md`和源码直接检查。

### 6.2 借鉴的外部项目

项目曾读取、重放并独立复核 VonEquinox 的 `DiskCoveringSolve` 相关材料，尤其是n=100外部下界/上界发布包。它的角色是外部参照和可重放输入，不是本项目自动继承的“权威证明”。第三方源码没有随本仓库分发；使用边界、哈希和重放记录见`docs/`中的external/absorption报告以及`verify/out/external-disk100-bounds-67ebf1c.json`。
