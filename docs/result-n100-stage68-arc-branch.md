# 阶段68：保留弧段的覆盖分支

## 实际执行

- `python verify/n100_boundary_arc_branch.py`：退出0，证书 `verify/out/n100-boundary-arc-branch.json`。
- `python verify/n100_boundary_arc_branch_audit.py`：退出0，证书 `verify/out/n100-boundary-arc-branch-audit.json`。

输入来自阶段67完整32案紧盒。按最小非单一顶点支持掩码大小、总掩码大小、placement字典序选择代表，选得[14,21,28,3]。它不是真实候选，不能从此代表推断其他31案结果。

## 分支语义

每个节点重新执行每象限256段弧筛选。达到固定点后，选择支持弧段最少且至少有2段的边界顶点，将支持索引按数量分成两组，各组对应弧片段与父顶点盒的交集取矩形外包，分别作为两个子盒。

两组索引互斥且并集恰为父支持集合。真实顶点必须位于单位圆周，且至少属于一个未拒绝弧段，所以两个子域覆盖所有父域中满足这些必要条件的解。这里不声称两个子矩形覆盖父矩形中的任意点；父矩形的离圆周部分本来就不属于待覆盖必要解域。闭弧端点可能被两个组同时包含，没有解丢失。

最多深度4；传播达到上限的节点直接保留。只有全部叶严格排除才能宣布代表根域排除。

## 结果

31节点：15 split、16 unresolved、0 excluded。根未排除，无新增严格排除，固定核心仍576排除、4200保留。

独立结构/终态审计用直接整数公式重建每组弧片段外包，核对每个父支持索引的完整二分、子输入盒、节点输出盒包含关系、深度与节点可达性，并重算固定节点终态支持掩码。全部通过。没有独立重放全部传播轨迹，拓扑设置和部分支持审计共享。

## 后续

本次确认了按支持弧段分支的覆盖语义可执行，但深度4没有产生空叶。下一步若继续，应保存并细化这16个未决弧域，或用共同圆心对多个边界顶点的联合支持约束减少伪组合，避免只重复选另一个代表。仍需完整核心枚举、精确半径代数描述及全局最优性。

machine_verified_geometry=false，global_optimality=false。圆周次序到核心的几何归约仍为解析依赖；未决叶不代表存在覆盖。
